Guía rápida de pruebas

Pasos para arrancar MADeCa en tu equipo, cargar la empresa de demostración y comprobar cada función con los documentos de ejemplo.

1. Qué necesitas

ElementoPara qué
Docker Desktop en marchaLevanta base de datos, Redis, la aplicación, el hot-folder y los conectores. Incluye WeasyPrint y Tesseract (PDF generado y OCR).
PowerShell 7 (pwsh)Script de pruebas de la API (demo\pruebas_api.ps1).
NavegadorPanel de empresa (http://localhost:8000/login) y de operador (/superadmin/login).
El entorno .venv del proyectoTests automáticos y conector local (ya existe en la carpeta del proyecto).
Todo lo de esta guía son datos ficticios de prueba. No uses la demo en una instalación real.

2. Arrancar (primera vez)

Desde la carpeta del proyecto (LAUNCHER\SCRIPTS\MADECA):

# 1. Configuración: revisa .env (si no existe, copia el de ejemplo)
Copy-Item .env.example .env          # solo si no tienes .env
#    En .env deja:  APP_ENV=development   APP_BASE_URL=http://localhost:8000
#    y pon claves propias en APP_SECRET_KEY y JWT_SECRET_KEY (distintas). Para generarlas:
.venv\Scripts\python -c "import secrets; print(secrets.token_urlsafe(48))"

# 2. Construir y arrancar todos los servicios
docker compose up -d --build

# 3. Crear o actualizar las tablas (también después de cada actualización)
docker compose exec app alembic upgrade head

Comprueba que responde: http://localhost:8000/salud debe devolver {"estado":"ok"}.

Si cambias APP_SECRET_KEY después de subir certificados, no se podrán descifrar: vuelve a subirlos.

3. Cargar la demo

docker compose exec app python -m scripts.cargar_demo --con-operador

Crea la empresa ficticia Distribuciones Demo SL (B00345678) y muestra una sola vez:

DatoUso
admin@demo.madeca.local + contraseñaPanel de empresa con todo: usuarios, integraciones, certificados, fuentes.
operador@demo.madeca.local + contraseñaCrear, modificar y finalizar expediciones; bandeja.
lectura@demo.madeca.local + contraseñaSolo consulta (para comprobar que no puede crear nada).
operador-plataforma@demo.madeca.local + contraseñaPanel de operador /superadmin (alta de empresas).
Clave de API mad_live_…Pruebas de la API y conector local. Guárdala en PowerShell: $env:MADECA_API_KEY = "mad_live_…"
Id de la empresaNombre de su carpeta en el hot-folder.

¿Has perdido las contraseñas o la clave? docker compose exec app python -m scripts.cargar_demo --con-operador --nuevas-claves genera otras y cierra las sesiones abiertas.

Están en demo\documentos\. Para regenerarlos con fechas de mañana: .venv\Scripts\python demo\generar_documentos.py.

6. Pruebas de la API

Con la aplicación en marcha y la clave de la demo:

$env:MADECA_API_KEY = "mad_live_..."
pwsh demo\pruebas_api.ps1                      # contra http://localhost:8000
pwsh demo\pruebas_api.ps1 -Url https://deca.tudominio.es

Recorre en orden: salud, PDF propio con QR, rechazo del escaneo, datos completos (camino 2), modificación, descarga de PDF y QR, escaneo a la bandeja, borrador del conector, entrega. Cada paso imprime lo que responde MADeCa en verde, o el motivo en amarillo/rojo. La documentación interactiva de todos los parámetros está en http://localhost:8000/docs.

7. Hot-folder

Con el Id de la empresa que mostró cargar_demo:

$id = "pega-aqui-el-id-de-la-empresa"
$base = "hotfolder_watch\incoming\$id\generico"
New-Item -ItemType Directory -Force "$base\pdf", "$base\datos" | Out-Null
Copy-Item demo\documentos\hotfolder\pdf\*   "$base\pdf"
Copy-Item demo\documentos\hotfolder\datos\* "$base\datos"

En unos segundos los ficheros pasan a hotfolder_watch\processed\ y aparecen dos expediciones (ALB-DEMO-HF-001 y ALB-DEMO-HF-002). Si algo falla, van a hotfolder_watch\errores\ con un .errores.txt que explica el motivo. Registro: docker compose logs -f hotfolder-watcher.

8. Conector local

# Carpeta de prueba con un albarán
New-Item -ItemType Directory -Force C:\Temp\madeca_conector | Out-Null
Copy-Item demo\documentos\01_albaran_erp.pdf C:\Temp\madeca_conector\

# conector.ini de prueba
@"
[madeca]
url = http://localhost:8000
[carpetas]
rutas = C:\Temp\madeca_conector
[estado]
fichero = C:\Temp\madeca_conector_estado.json
registro = C:\Temp\madeca_conector.log
"@ | Set-Content conector_local\conector.ini -Encoding utf8

$env:MADECA_API_KEY = "mad_live_..."
.venv\Scripts\python conector_local\conector.py --una-vez

Resultado: «Enviado 01_albaran_erp.pdf → borrador …» y un borrador nuevo en la bandeja (origen api:conector_local), sin documento original (no salió del equipo). Si lo ejecutas otra vez no repite el envío. Sin Tesseract instalado en Windows, los escaneos llegan sin datos y con aviso; los PDF con texto funcionan siempre.

9. Fuentes de datos

Como admin, menú Fuentes de datos. Sin credenciales reales de SharePoint, Odoo, etc. puedes comprobar:

  • Crear una fuente (p. ej. Dropbox con datos inventados) → aparece en la lista; al editarla, los secretos salen vacíos con «Guardado».
  • Probar → mensaje rojo con el motivo (credenciales rechazadas): es lo esperado.
  • Odoo o SAP con dirección https://127.0.0.1 o https://10.0.0.5 → Probar responde «apunta a una red privada… no permitido» (protección SSRF).
  • Pausar/Activar y ✕ (eliminar).
  • OCR de documentos escaneados: sin Azure configurado indica «Esta instalación no tiene Azure configurado».

Para una prueba completa sin servicios externos, activa la carpeta del servidor: en .env pon FUENTES_CARPETA_BASE=/app/storage/fuentes, reinicia (docker compose up -d), crea la carpeta de la empresa con docker compose exec app mkdir -p /app/storage/fuentes/<id>, copia un PDF con docker compose cp demo\documentos\01_albaran_erp.pdf app:/app/storage/fuentes/<id>/ y crea la fuente «Carpeta del servidor». Leer ahora → «1 nuevo(s) en la bandeja».

10. Firma con certificado

Certificado autofirmado solo para pruebas (no vale como firma real):

$c = New-SelfSignedCertificate -Subject "CN=Demo MADeCa" -CertStoreLocation Cert:\CurrentUser\My -KeyExportPolicy Exportable -KeySpec Signature -KeyAlgorithm RSA -KeyLength 2048
Export-PfxCertificate -Cert $c -FilePath C:\Temp\certificado_demo.p12 -CryptoAlgorithmOption AES256_SHA256 -Password (ConvertTo-SecureString "demo1234" -AsPlainText -Force)

Como admin: Certificados → sube certificado_demo.p12 con contraseña demo1234. Crea una expedición marcando Finalidad contractual → en el detalle aparece «Firma: AdES». Desactiva el certificado y repite → error «no tiene ningún certificado de firma activo y vigente». Al terminar puedes borrar el certificado de Windows desde certmgr.msc (Personal → Certificados → «Demo MADeCa»).

11. Tests automáticos

.venv\Scripts\python -m pytest tests -q

Resultado esperado: 120 passed, 2 skipped. Los 2 omitidos son del PDF generado con WeasyPrint, que en Windows sin GTK no puede ejecutarse (en Docker sí). No necesitan base de datos ni Docker: los servicios externos se simulan.

12. Parar y volver a empezar

ComandoQué hace
docker compose stopPara los servicios. Los datos se conservan.
docker compose up -dLos vuelve a arrancar con los datos que había.
docker compose up -d --buildTras actualizar el código. Después: docker compose exec app alembic upgrade head.
docker compose down -vBorra todo: base de datos, PDF y certificados de los volúmenes. Solo para empezar la demo desde cero.
docker compose down -v no tiene vuelta atrás. No lo uses en una instalación con datos reales.

13. Si algo falla

ProblemaCausaSolución
La app no arranca: «APP_SECRET_KEY debe ser un valor aleatorio…»APP_ENV no es development y las claves son las de ejemplo.Pon APP_ENV=development para pruebas, o claves propias de 32+ caracteres.
«relation … does not exist»Faltan las tablas o las migraciones nuevas.docker compose exec app alembic upgrade head.
«APP_BASE_URL debe usar HTTPS»URL base con http y distinta de localhost.En pruebas: APP_BASE_URL=http://localhost:8000.
El QR del móvil no abre nadaEl QR apunta a localhost, que en el móvil es el propio móvil.Normal en local. Pruébalo abriendo la URL en el equipo, o usa la IP del equipo en APP_BASE_URL (solo pruebas).
El OCR no lee nada en la bandejaImagen ilegible o sin Tesseract (fuera de Docker).En Docker viene instalado. Fuera, instala Tesseract con el idioma español o indica su ruta en TESSERACT_RUTA.
Camino 2 / «Generar documento» falla con «WeasyPrint no puede cargar…»Se está ejecutando fuera de Docker en Windows.Usa Docker (la imagen trae las librerías).
El hot-folder no procesaCarpeta mal formada o empresa inexistente/desactivada.Mira hotfolder_watch\errores\*.errores.txt y docker compose logs hotfolder-watcher.
La API responde 401Clave revocada, mal copiada o no definida.Revisa $env:MADECA_API_KEY; genera otra en Integraciones ERP.
Fuente con error «apunta a una red privada»Protección SSRF.Correcto en la nube. Solo en instalaciones propias: FUENTES_PERMITIR_RED_PRIVADA=true.
